Flow A Planned Session — session EigenVertex existante choisie dans la liste knowledge_session_id ≠ null
POST /knowledge-sessions/{id}/recorder-sync

Réconcilie la session existante avec le formulaire recorder et la géolocalisation au moment du tap START. Le recorder est toujours la source de vérité — sa localisation écrase celle entrée auparavant dans l'app. Le backend MERGE metadata_json, ne remplace pas.

Body — application/json
{
  "project_id":     uuid | null,
  "title":          string,           // valeur du formulaire recorder
  "session_type":   KnowledgeSessionType,
  "mode":           "online",
  "subject":        string | null,
  "agenda":         string | null,
  "location_label": string | null,   // adresse géocodée ou saisie manuelle
  "geo_lat":        float | null,
  "geo_lng":        float | null,
  "participants":   [{ "display_name": string }] | undefined,
  "metadata_json": {
    "recorder_surface": "existing_session_form",
    "location_source":  "recorder_geolocation" // | "manual_entry" | "unavailable"
  }
}

Réponse : 200, pas de body. Échec → exception, fallback offline (status local "draft", recorded_offline: true).

Phase 2 — Recording

Deux modes exclusifs selon syncMode : stream (authentifié + online) ou local (offline ou non-authentifié).

Stream mode syncMode==='stream' && online

PCM 16 kHz mono → WebSocket temps réel. Chaque frame = 320 ms / 5 120 Int16-LE / 10 240 octets. Reconnect automatique ×3 (back-off linéaire 1,5 s).

URL WebSocket
wss://api.eigenvertex.com/v1/knowledge-sessions/
{id}/audio-stream?device_id={device_id}

Backup local : MediaRecorder parallèle sur le flux amplifié (96 kbps, audio/mp4 iOS) → blob sauvegardé dans IndexedDB au stop pour Share Audio uniquement. Pas uploadé via /audio-chunks.

Local / Offline !online || !authed

MediaRecorder (web) ou AVAudioRecorder (iOS natif). Aucun trafic réseau pendant l'enregistrement — tout sauvegardé dans IndexedDB.

  • 1.
    Pendant l'enregistrement

    Chunk émis toutes les 5 s (DEFAULT_CHUNK_MS).
    Chaque chunk → IndexedDB.chunks_data, statut "saved".
    MIME iOS/Safari : audio/mp4.
    MIME Chrome/desktop : audio/webm;codecs=opus.

  • 2.
    Au stop — flush vers /audio-chunks

    Si knowledge_session_id + isOnline + syncMode ≠ "local" : tous les chunks "saved" ou "pending_sync" sont uploadés en parallèle via Promise.allSettled.

Purement offline (pas de knowledge_session_id) : les chunks restent dans IndexedDB indéfiniment. Share Audio exporte le blob local — pas d'upload automatique.

Phase 3 — Stop

Appelée par _finalizeStop() après arrêt de la capture audio. Condition globale : knowledge_session_id ≠ null && isOnline && syncMode ≠ "local".

Local mode uniquement Upload des chunks avant /stop
POST /knowledge-sessions/{id}/audio-chunks

Un appel par chunk, en parallèle (Promise.allSettled). En stream mode, cet appel n'est jamais émis — l'audio a déjà transité par WebSocket frame par frame.

Body — multipart/form-data
ChampTypeDescription
audioFileBlob audio — filename chunk_0000.m4a / .webm
device_idstringUUID du device (réponse /devices)
chunk_indexintIndice séquentiel depuis 0
start_msintOffset début dans la session (ms)
end_msintOffset fin dans la session (ms)
mime_typestringaudio/mp4 ou audio/webm;codecs=opus
size_bytesintTaille du blob en octets
local_session_iduuidIdentifiant IndexedDB local de la session

Sur échec individuel : chunk reste "saved" dans IndexedDB, pas de retry automatique. /stop est appelé même si des chunks ont échoué.

POST /knowledge-sessions/{id}/stop

Clôture la session côté backend. Appelé après session_commit WebSocket (stream) ou après le flush /audio-chunks (local). Pas de body.

Succès → statut local "synced". Échec réseau → statut "stopped_local" — la session reste valide, l'audio est préservé dans IndexedDB.
