2 · Flow A — Record Now (Online) · PCM Stream Mode

When the user is authenticated and online, Record Now creates a voice note and streams audio in real-time over WebSocket. No local audio chunks are uploaded via HTTP — only the backup blob is stored locally for Share Audio.

Backup blob (local only — NOT uploaded via HTTP) A parallel MediaRecorder saves a local WebM/M4A blob (~200 KB for 12s) to IndexedDB with status backup_only. It is used only for the Share Audio action (iOS share sheet). It is never sent to /audio-chunks. The client explicitly skips backup_only chunks in all upload loops.
3 · Flow B — Record Now (Offline) → Reconnect → Sync

When offline (airplane mode + WiFi off), audio is saved locally as N chunks (default 5 s each) in IndexedDB. On reconnect the user triggers a manual sync. The client creates a new backend session and uploads all chunks via HTTP multipart.

Creates a NEW session (same payload as A1) · mode: "online" even for an offline-recorded session · returns { id }

Empty body

Repeated N times (one per chunk) · multipart/form-data · see payload B1
05

Payload B1 — Audio chunk upload (multipart/form-data)

// POST /v1/knowledge-sessions/{id}/audio-chunks
// Content-Type: multipart/form-data (boundary set by browser)

audio            → <Blob>      chunk_0000.webm  // audio/webm;codecs=opus on iOS web
                               chunk_0000.caf   // audio/x-caf on iOS native recorder
device_id        → <string>   "dev-uuid…"
chunk_index      → <integer>  0                // 0-based
start_ms         → <integer>  0
end_ms           → <integer>  5001             // Math.round() applied — see §3.1
mime_type        → <string>   "audio/webm;codecs=opus"
size_bytes       → <integer>  118432
local_session_id → <string>   "local-uuid…"   // client-side ID, for idempotency
Error encountered (now fixed client-side) — T5 Sync failed at "upload chunk 0": Input should be a valid integer, unable to parse string as an integer (×2)

Root cause: On iOS, NativeAudioRecorder (AVAudioEngine) returns startMs/endMs as Swift Double values (e.g. 5001.5). FormData serializes them as "5001.5", which FastAPI's integer validator rejects.

Client fix applied: Math.round() on all integer form fields before form.append() in uploadAudioChunk(). The backend received clean strings like "5001", accepted them, and the sync succeeded.
Backend recommendation Consider accepting form integer fields with lax coercion (Pydantic model_config = ConfigDict(coerce_numbers_to_str=False) / standard lax mode) so that "5001.5" rounds to 5001 server-side as a safety net. The client now sends clean integers, but defensive handling costs nothing.
Important: session_type mapping for offline flush Client-side sessions of type free_recording are mapped to voice_note on the wire (POST /knowledge-sessions) for the offline flush path. This is intentional — free_recording is a client-only concept for "Record Now without filling a form".
4 · WebSocket PCM Stream Protocol
StepDirectionMessageDetails
1 Client → Server session_hello (JSON) { type: "session_hello", session_id, device_id }
2 × N Client → Server audio_frame_meta (JSON) { type: "audio_frame_meta", frame_index, timestamp_ms, duration_ms: 320, sample_rate: 16000, channels: 1, encoding: "pcm16le", byte_count: 10240 }
2 × N Client → Server Binary frame 10,240 bytes · Int16 LE · mono 16 kHz · 320 ms/frame · ~108 frames/35 s
3 Client → Server session_commit (JSON) { type: "session_commit", total_frames, total_bytes }
4 Client → Server WS close(1000) Normal closure · followed immediately by POST /stop
PCM capture pipeline (client-side) getUserMedia → AudioContext @ 16 kHz → GainNode (×10 on iOS for usable levels) → AudioWorkletNode → LiveStreamClient (WebSocket). Fire-and-forget — no per-frame ACK expected from server. The WebSocket is kept open for the full session duration.

6 · Backend Action Items
⚠ Integer fields in multipart — defensive coercion
Fields chunk_index, start_ms, end_ms, size_bytes arrive as strings in multipart/form-data (browser spec). FastAPI's Pydantic validator correctly coerces "5001" → 5001. Client now sends clean integer strings (Math.round applied). Recommend keeping standard lax coercion enabled as a safety net for future clients.
ℹ voice_note session_type — confirmed working
The offline flush path POSTs session_type: "voice_note" to create a session. This was suspected as a possible enum validation failure earlier (original error was "[object Object]" — unreadable). After fixing error serialization on the client, the actual error was revealed to be the integer issue above. voice_note itself is accepted by the backend.
ℹ audio/x-caf chunks from iOS native recorder
When the app uses the native iOS recorder (AVAudioEngine), offline chunks arrive as audio/x-caf stereo 48 kHz. The backend /audio-chunks endpoint should support this mime type in addition to audio/webm. The client sends mime_type in the form data for server-side routing.
✓ local_session_id field in /audio-chunks
The client sends a local_session_id (client-generated UUID) alongside each chunk. This is intended for idempotency — if a sync is retried, the backend can deduplicate chunks by this ID. No retry logic is implemented on the client yet, but the field is always present.
7 · Error Handling — FastAPI Validation Errors

FastAPI returns validation errors as:

// HTTP 422 — body structure
{
  "detail": [
    { "type": "int_parsing", "loc": ["body", "start_ms"], "msg": "Input should be a valid integer…", "input": "5001.5" },
    { "type": "int_parsing", "loc": ["body", "end_ms"],   "msg": "Input should be a valid integer…", "input": "18400.7" }
  ]
}

The client now serializes detail arrays by joining .msg fields with ; , producing readable error messages. Error attribution by step ("Sync failed at step: message") was also added to the offline flush flow.
